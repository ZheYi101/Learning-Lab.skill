# 教学反馈

先选一个学完就能评价的单位。把对应材料、AI 预估和用户实际反馈记在同一行，便于后来对照。用户可以跳过反馈继续学。

## 每课一次

- 课程站点、分课页面和已有章节的长材料，默认学完一课给一次整体读感。1 分表示读得费力，3 分表示大体跟得上，5 分表示读得顺且有收获。用户可以只给一个数，或只写一句感受。课程页把选分和保存做成一次点击，把补充原因放在选填入口。
- 正文定稿后，记录课程标题、可定位的入口和简短摘要。用一个整体分作为 AI 预估。用户分数在本人给出后另填。课程页导出时，整课用同一个回执编号，独立保存留言。
- 评分单位随用户要求调整。用户想知道某一句为什么费力、要求比较写法，或已经给出具体段号时，可以按下面的分项反馈继续。

## 细看段落

用户明确想比较若干段时，按自成一段的讲解留原文及换行。共同解释同一关系的公式、图或小表可随段。用回执段号标原文，读完若干段后可一起反馈。对话里只标段号，AI 预估留在表里。

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 好懂 | 看不出来龙去脉 | 大意懂了，仍有一个关键说不清 | 能跟上并用自己的话说出意思 |
| 读得顺 | 常停下来猜指代或重读 | 有一两处需要停一下 | 句子和推理都跟得上 |
| 有趣 | 觉得无聊或与自己关系弱 | 可以读下去 | 熟悉的情境或问题让我想继续 |

## 本地记录

把 UTF-8 JSON 送入 `python -B -X utf8 "<本技能目录>/scripts/feedback.py" add`。每个 `paragraphs` 项对应本次所评的一课或一段。整课的 `estimate` 写一个整数，分项写三个整数。复用相同材料的回执编号。PowerShell 管道显式使用 UTF-8。

~~~json
{
  "date": "2026-11-23",
  "topic": "手套硬件课程",
  "paragraphs": [
    {"text": "第 1 课 · 一颗 IMU 的数据怎样到达主机\n课程入口和摘要", "estimate": 4}
  ]
}
~~~

用 `feedback.py rate` 批量写回。整课的 `rating` 写一个整数。分项按好懂、读得顺、有趣的顺序填写，`null` 保留该项原值。只说感受时写 `note`。

~~~json
{
  "ratings": [
    {"id": "P034", "rating": 4},
    {"id": "P001", "rating": [4, null, 3], "note": "从第二句开始需要重读"},
    {"id": "P002", "note": "先举 Vue 的例子，我就懂了"}
  ]
}
~~~

用户也可以直接回填知识库根目录下的 `教学段落反馈.md`。整课评分写作「整体 4」，分项写作 `4/2/3`。定位不唯一时，回显课名或一句原文供确认。工具无法登记时如实说明，学习照常继续。

## 回收后写回

- 用课名、具体例子和回执定位原记录，保留本人分数和留言。整体分用来校准读感预估。讲法的具体改动依据用户指出的术语、类比或推理步骤。需要对照近期反馈时，用 `feedback.py recent --reviewed --limit 6`。
- 找到可复用的改法时，把它放到以后做相同教学判断的地方。比如用户指出高地址分配讲不清楚，可以把串联规则讲成两个动作，先按首次适应选空闲区，再用所选区的终址确定划分位置。本人已授权持续改进时，优先调整本技能中对应的指引。
- 按[本地写回约定](knowledge-writeback.md)记录会改变下次起点的证据。自述做完某道题可以记入经历。明确指出的概念卡点可以记入对应能力并标为待确认。记录作答时保留实际给过的提示。能力状态依据本人作答、实作或明确的能力自述更新。
- 用户明确希望持续用反馈改进讲法与个人库时，将约定登记为学习偏好。已交付材料按用户当次要求调整。
