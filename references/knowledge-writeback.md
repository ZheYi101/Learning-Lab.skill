# 学习时如何写回

写回的单位是以后会用到的一个变化。用户只过一遍考纲，当次可以没有新增记录。以前参与过项目、今天独立写出、看了提示才做出，各自写到实际有依据的那一步。

## 从用户的话决定写到哪里

| 发生了什么 | 写到哪里，怎么更新 |
| --- | --- |
| “我上过操作系统，但这个实验我没做。” | 查原课程和对应能力。课程保留，若有错误归属，更新原条，写明这次澄清。只有用户实际答出的环节才能作为作答依据。 |
| 以前做过，现在说忘了 | 更新同一能力。把原工程依据留在历史，把现在生疏的具体环节和自述日期写进最近记录，状态可改为需回顾。 |
| 在学习中做出一步，或在某个条件上明确卡住 | 留题目条件、是否看过示例、用户实际做出或卡住哪一步。只有关乎下次教学起点时才收。在同一段演示中跟做和隔天独立完成应有不同记录。 |
| 又在一个项目遇到相同机制 | 先找已有动作。新来源会影响教学时，在原条追加来源或例子，保留当前独立程度。另起条目需要一个会改变教法的不同动作。 |
| “以后复习考试都先讲范围”“这次先别出题” | 前者更新具体场景的偏好，后者只指导本次。AI 想试一种讲法可以当场试，用过一次或从项目里猜到的偏好不自动成为长期设置。 |
| “以后别再用这个偏好”“刚才那条记错了” | 更新原键为停用，或写入更正和原因。下次只采用有效偏好和最新事实。 |

## 写回命令

1. 读当前对话确认原话、条件和日期。查重用 `python -X utf8 "<本技能目录>/scripts/knowledge.py" find --group 全部 "动作或课程"`。打开可能相同的条目，取其现有文件名作稳定键。偏好按 `学习偏好.md` 的场景键更新。需要区分“停用过”和“从未设置”时看原文件。
2. 对 `python -X utf8 "<本技能目录>/scripts/record.py"` 的标准输入送入一个 UTF-8 JSON 对象。用结构化序列化传递文本。Windows PowerShell 管道应显式使用 UTF-8。两个脚本共用技能目录的配置，`--root` 可在测试时指定临时库。
3. 所有请求含 `group`（经历、能力、偏好）、`key`（稳定键）、`date`、`source`（谁在什么情境中提供）、`text`（具体表现或偏好）。经历新建给 `kind`。能力新建给 `state`、`basis`。偏好给 `status`（明确、试用、停用）。依据从过去的实作转为本人对现状的自述时，同步更新 `state` 与 `basis`。`date` 写本次观察或澄清的日期，过去事件发生的日期写在正文里。补录一个早于最近记录的观察时按该观察日期归入历史。`reason` 记录更正的缘由。更正会使旧的教学借用失效，若仍有适用的旧例，给出更正后完整的 `teaching`。也可用空字符串明确撤回旧建议。能力与已有课程或项目相关时用 `experiences` 给出对应经历的稳定文件名（省略 `.md`）以增补链接。这样以后用课程名续学也能找到该次作答。`refs` 为可追溯的来源列表，`cues` 给出时替换当前关系词列表，省略时保留原值，`teaching` 是旧例中可借的步骤和适用边界。只传有依据的字段。相同事件重试可复用 `event_id`。不要把示例输入写入真实库。
4. 读取命令回执。写后以 `recall`、`preferences` 或原文件检查变更是否已生效。冲突或证据不一致时先重读原条并保留双方来源。写入失败就直说记录仍待保存，学习照常进行。

下例只用于说明能力字段。假设学生在独立练习中给出一个具体判断，可以向脚本输入：

```json
{
  "group": "能力",
  "key": "给出等待关系时指出循环",
  "date": "2026-11-19",
  "source": "示例中的课堂作答",
  "text": "题面给出两个线程各持有一把锁，学习者无提示指出二者互相等待。",
  "state": "独立可用",
  "basis": "作答",
  "cues": ["循环等待"],
  "teaching": "可借用两条等待边讲有向环，多实例资源的判定条件需另讲。"
}
```

撤回的写法、过时的教学建议和旧的掌握状态可以留在历史，教学检索应只据当前记录判断。个人知识库不保存完整对话或每一次练习的流水账。
